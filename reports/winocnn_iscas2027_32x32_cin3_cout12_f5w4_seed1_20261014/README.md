# WinoCNN ASIC rerun — ISCAS 2027

Run ID: 20261014-32x32-cin3-cout12-f5w4-seed1
Branch: `iscas2027`
Source revision before the run: `776c144215fe389b7b8d3e74284481cd6d277c5d`
Top: `wino_systolic_top`

This run uses the paper-branch WinoCNN configuration, F(2x2,3x3), with 2 PEs (M=2, N=1, Q=1, B=1), or 32 scalar Winograd-domain multipliers. The data are generated by the WinoCNN-style modulo RNG, not from FastConv.

## Workload and data

- Input: 32x32, Cin=3; output: 32x32, Cout=12; 3x3 kernel, stride 1, padding 1.
- Signed feature values: 5 bits, [-16, 15]. Signed weights: 4 bits, [-8, 7]. Seed 1, glibc `random()`.
- Scale 128; ReLU disabled; batch 1.
- The generated feature, weight and golden-output `.bin` files are binary. The `.hex` memory stimulus files are ASCII text, but are generated data as well; none are included in Git. Their preserved copies and hashes are listed in [artifacts_external.md](artifacts_external.md).

## Reproduction

On Paxos, load the recorded tools:

```sh
source /etc/profile.d/modules.sh
module use /soft64/modulefiles
module load xilinx/vivado/2019.2 cadence/xcelium/2303 cadence/genus/211
```

Generate data outside the repository and prepare the matching C-sim golden:

```sh
RUN=/sim/tarsio.onofrio/artifacts/wino-iscas2027-20261014-32x32-cin3-cout12
python3 asic_scripts/generate_winocnn_modulo_dataset.py \
  --height 32 --width 32 --cin 3 --cout 12 --kernel 3 \
  --feature-bits 5 --weight-bits 4 --seed 1 --out "$RUN/dataset"
bash asic_scripts/prepare_asic_stimulus.sh \
  32 32 3 32 32 12 3 3 1 1 1 0 128 \
  "$RUN/dataset/feature.bin" "$RUN/dataset/weight.bin" \
  testbench/stim/dom4 3
bash asic_scripts/run_asic_flow.sh all
```

The recorded run executed the stages separately (HLS, RTL/golden, Genus, gate-SDF/golden, Joules) after preparing the stimulus. The final checked-in HLS script now avoids the unnecessary IP-catalog export and exits after `csynth_design`; HLS 2019.2 otherwise failed on this 2026 host with `bad lexical cast` while converting the generated `core_revision` value. `csynth_design` itself generates the Verilog consumed by Genus.

## Results

- C simulation vs integer golden: PASS (`Not different!`).
- RTL vs golden: PASS, 4096/4096 output writes checked, 0 mismatches.
- Gate-level simulation with nominal SDF vs golden: PASS, 4096/4096 writes, 0 mismatches.
- Genus TSMC 28 nm: 64,821.456 um^2 cell area; 19,252 sequential and 31,151 combinational instances. The 2 ns target has 39.4 ps slack at the 0.81 V / 125 C slow corner and 0 violating paths in the reported STA view.
- Joules, nominal 0.90 V / 25 C, driven from the gate-level SHM: 10.8059 mW average. The measured simulation count is 52,453 cycles; at the 2 ns target period this is 104.906 us. `10.8059 mW x 104.906 us = 1133.6 nJ` is an estimate from average power times run time, not a directly integrated energy result.
- Memory macros are external/blackboxed and excluded from the reported area and power.

Traffic counters from the gate testbench: 1,120 input reads, 2,232 weight reads, 129 parameter reads, and 4,096 output writes.

### SDF limitation

The nominal SDF was read and annotation completed. Xcelium reports 271,429/271,437 path delays annotated (100.00%), but only 66,834/182,168 timing checks (36.69%). It also emits a `FLFNOF` warning for an annotation-command line without an SDF file. Therefore this is a gate-level simulation with SDF delay annotation and golden checking, but it is **not** complete timing-check annotation or timing signoff. The Genus STA result is reported separately.
